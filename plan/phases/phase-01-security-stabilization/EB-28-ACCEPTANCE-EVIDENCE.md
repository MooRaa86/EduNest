- Filesystem review: `FileStorageService` applies `0600` to completed private files on POSIX filesystems, but creates directories without explicit permissions; their modes depend on the process umask and existing directories. The Dockerfile creates `uploads` and does not specify a runtime `USER`; mounted-volume ownership, ACLs and other deployments are not established by the repository. Operations must restrict write/rename access to the upload tree and its ancestors to trusted service/administrative principals and verify the actual runtime identity, directory modes and volume ACLs. `toRealPath()` containment is checked separately from `Files.newInputStream()`: a principal able to replace path entries between those operations may race the check. Static symlink tests do not prove safety against that race; a trusted-write-only tree is an operational mitigation, not a race-free open.
- The legacy `GET /files?filePath=` handler returns 403 for authenticated requests with the required parameter; anonymous requests are rejected by the production chain. This cross-scope temporary safeguard prevents an ownership bypass but departs from D-06's guard-first default and breaks existing callers. Eng Lead / FE approval is not yet recorded; EB-27 remains open for an ownership-aware replacement. Reverting without a coordinated equivalent would leave private files retrievable by authenticated strangers.
